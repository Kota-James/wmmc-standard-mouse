## 要旨

- 現行コードは「配布して走る」完成度が高く、リファレンスとして保存する価値がある
- 一方で `#ifdef MAIN_C_` によるグローバル変数、`global.h` の一括 include、
  マジックナンバー、コメントと実装の不一致、未探索状態での二次走行フリーズなど、
  教材として引き継ぐには構造・品質の両面で課題がある
- 提案の骨子は **2 層分離**: ハードウェア層（Platform）は完成品として配布し、
  壁判定・制御・マップ・足立法・走行戦略（App）を新入生の実装課題にする。
  App を HAL 非依存にすることで PC シミュレータ・自動採点・MCU 移植性が同時に手に入る

## 決定済みの方針（2026-07）

- **標準プログラムは C のまま**とし、新入生向け実装（穴あき教材）+ マイコン移植を
  考慮した App/Platform 分離を一体の改修として行う
- 配布は **Template repository 方式**（各部員が個人リポジトリを作る。02 §5）。
  先輩によるレビューは希望者向けの選択肢とし、品質の底は課題の自動チェックで保証する
- **C++ 化（03）は標準プログラムには適用しない**。個人リポジトリで挑戦する
  上級生向けガイドとして位置づける
- 改修は「挙動を変えないバグ修正 → 構造分離（C のまま）→ 教材化」の順で行う（05 §6）
