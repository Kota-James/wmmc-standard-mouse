# 環境構築ガイド（Windows / macOS / Ubuntu）

新入生が最初にやる環境構築を OS 別にまとめる。
迷ったら部で一番ユーザーが多い **Windows + WSL** の構成を勧める。

## 0. 必要なものの全体像

| ツール | 用途 | Windows | macOS | Ubuntu |
|---|---|---|---|---|
| STM32CubeIDE | ファームのビルド・書き込み・デバッグ | Windows 版 | mac 版 | Linux 版 |
| Git | バージョン管理（[Git入門](Git入門.md)） | Git for Windows | Xcode CLT に同梱 | apt |
| シリアルターミナル | printf の閲覧（115200bps） | Tera Term | screen（標準） | screen など |
| gcc + make | シミュレータ（`Sim/`）のビルド | WSL 内に導入 | Xcode CLT に同梱 | apt |
| arm-none-eabi-gcc（任意） | コマンドラインでのファームビルド | WSL 内に導入 | brew | apt |

CubeIDE のダウンロードには ST のアカウント登録（無料）が必要。

---

## 1. Windows（推奨: CubeIDE は Windows 側、Sim は WSL 側）

### 1-1. Windows 側

1. [STM32CubeIDE](https://www.st.com/ja/development-tools/stm32cubeide.html) をインストール
2. [Git for Windows](https://gitforwindows.org/) をインストール（設定はすべて既定値でよい）
3. [Tera Term](https://teratermproject.github.io/) をインストール
   （マウス接続後、シリアルポート → ST-Link の COM ポート → 115200bps）

### 1-2. WSL（Ubuntu 24.04）側 — シミュレータ用

PowerShell（管理者）で:

```powershell
wsl --install -d Ubuntu-24.04
```

再起動後、Ubuntu のターミナルで（ここから下は sudo が必要）:

```sh
sudo apt update
sudo apt install -y build-essential git
# 任意: コマンドラインでファームもビルドしたい場合
sudo apt install -y gcc-arm-none-eabi libnewlib-arm-none-eabi
```

リポジトリは WSL 側（`~/` 以下）にクローンし、シミュレータは WSL で動かす。
CubeIDE から同じフォルダを開くときは `\\wsl$\Ubuntu-24.04\home\<ユーザー名>\...`
を Import すればよい（Windows 側に別途クローンしても構わないが、二重管理に注意）。

> **書き込みは Windows 側の CubeIDE から行う。**
> WSL から ST-Link を直接使うのは usbipd-win による USB パススルーが必要で
> 上級者向け。新入生はやらなくてよい。

## 2. macOS

1. コマンドラインツール（gcc / make / git がまとめて入る）:
   ```sh
   xcode-select --install
   ```
2. [STM32CubeIDE](https://www.st.com/ja/development-tools/stm32cubeide.html) の
   macOS 版をインストール（Apple Silicon / Intel とも可）
3. シリアルは標準の `screen` で見られる（終了は `Ctrl-a` → `k` → `y`）:
   ```sh
   ls /dev/tty.usbmodem*        # マウス接続後にポート名を確認
   screen /dev/tty.usbmodem<番号> 115200
   ```
4. 任意（コマンドラインでのファームビルド）:
   ```sh
   brew install --cask gcc-arm-embedded
   ```

---

## 3. Ubuntu 24.04（ネイティブ）

1. 基本ツール:
   ```sh
   sudo apt update
   sudo apt install -y build-essential git
   # 任意: コマンドラインでのファームビルド
   sudo apt install -y gcc-arm-none-eabi libnewlib-arm-none-eabi
   ```
2. [STM32CubeIDE](https://www.st.com/ja/development-tools/stm32cubeide.html) の
   Linux 版（.deb）をインストール。インストーラが ST-Link の udev ルール
   （USB デバイスへのアクセス許可）も設定してくれる
3. **シリアルポートの権限**（Linux で一番ハマる箇所）:
   ```sh
   sudo usermod -aG dialout $USER
   ```
   を実行して**一度ログアウト→ログイン**する。これをしないと
   `/dev/ttyACM0` が Permission denied になる
4. シリアルの閲覧:
   ```sh
   screen /dev/ttyACM0 115200
   ```

---

## 4. sudo（管理者権限）が必要な操作のまとめ

新入生が `sudo` を打つのは以下だけ。**それ以外で sudo を要求される手順に
なったら何かがおかしいので先輩に相談**すること。

| OS | コマンド | 目的 |
|---|---|---|
| WSL / Ubuntu | `sudo apt install ...` | ツールの導入 |
| Ubuntu | `sudo usermod -aG dialout $USER` | シリアルポートの読み書き権限 |
| Ubuntu | CubeIDE の .deb インストール | IDE 本体と udev ルール |
| Windows | `wsl --install`（管理者 PowerShell） | WSL の導入 |

## 5. 動作確認チェックリスト

環境ができたら [課題0](exercises/00_開発環境とLチカ.md) に進む前に確認:

- [ ] `git --version` が表示される
- [ ] CubeIDE でこのプロジェクトを Import してビルドが通る（0 errors）
- [ ] マウスを USB 接続して書き込みができる
- [ ] シリアルターミナルに起動バナーが出る
- [ ] `cd Sim && make` がエラーなく終わる

> シミュレータは**ビルドが通ることだけ**を確認する。配布時点では課題4（`maze.c`）と
> 課題5（`solver.c`）が未実装なので、`./sim mazes/empty.maze` を実行すると
> 「不正な経路データ」「探索走行 失敗」になり `make test` も全 FAIL する。
> **これは正常**で、課題4・5 を実装すると PASS に変わる。

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 書き込めない | USB ケーブルが充電専用（通信線なし）。ケーブルを変える |
| シリアルに何も出ない | ボーレートが 115200 以外 / ポート選択ミス / （Ubuntu）dialout 権限（§3-3） |
| `./sim mazes/empty.maze` が「失敗」になる | 課題4・5 が未実装なら**正常**（§5 の注記）。実装後も失敗するなら実装のバグ |
| WSL で `./sim` が動くのに Windows で動かない | Sim は WSL（または mac/Linux）用。Windows 側で動かす必要はない |
| 日本語コメントが文字化けする | CubeIDE の Text file encoding を UTF-8 に（課題0参照） |
| `make: command not found` | §1-2 / §2-1 / §3-1 のツール導入を飛ばしている |
