# 課題の進め方

## 全体像

このプログラムは 2 つの層に分かれている。

- **platform 層**（`Core/Src/platform/`）: タイマ・ADC・Flash などマイコン固有の処理。
  完成品として提供されるので触らなくてよい
- **app 層**（`Core/Src/app/`）: マウスの「頭脳」。**ここを自分で実装するのが課題**

配布時点の app 層には、関数の枠とコメントだけがあり中身が `// TODO` になっている
箇所がある。課題 1 から順に埋めていくと、最終的に迷路を探索して走るマウスが完成する。

## 課題一覧

| # | 課題 | 実装するファイル | 実機 | 合格条件 |
|---|---|---|---|---|
| 0 | [開発環境とLチカ](00_開発環境とLチカ.md) | `app/app_main.c`（1行） | 必要 | ビルド・書き込み・printf 確認と最初のコミット |
| 1 | [壁判定](01_壁判定.md) | `app/wall.c` | 必要 | センサチェックモードで壁の有無が正しく表示される |
| 2 | [壁沿い制御](02_壁沿い制御.md) | `app/control.c` | 必要 | 直線コースを壁にぶつからず走り切る |
| 3 | [左手法](03_左手法.md) | `app/lefthand.c` | 推奨 | ループのない迷路でゴール到達 + 失敗する迷路の説明 |
| 4 | [マップ記録](04_マップ記録.md) | `app/maze.c` | 不要 | シミュレータの `make test` で CRASH しない |
| 5 | [足立法](05_足立法.md) | `app/solver.c` | 不要 | `make test` で全迷路 PASS |
| 6 | [走行戦略](06_走行戦略.md) | `app/strategy.c` | 必要 | 実機で探索走行→二次走行が完走する |

課題 4・5 は実機なしで進められる（`Sim/` のシミュレータを使う。課題 3 も
`--lefthand` オプションでシミュレータ実験ができる）。
実機の台数が足りないときは 4・5 を先にやってもよい。

全課題を終えた人向けの追加課題（模範解答なし・自由実装）:
- **オートスタート**（Mode 4 の空きモード。app_main.c のコメント参照）
- **マップダンプ**（Mode 5 の空きモード。探索結果の可視化。同上）

分からない用語が出てきたら [用語集](../用語集.md) を見ること。

## 行き詰まったら

1. まず該当ファイルの先頭コメントと、ヘッダ（`Core/Inc/app/*.h`）の説明を読み直す
2. シミュレータや printf で「何が期待と違うか」を具体的にしてから考える
3. それでも詰まったら先輩に聞く。**「どこまで分かって、どこからが分からないか」を
   言えるようにしてから**聞くと、自分にも先輩にも実りが大きい
4. 模範解答は `reference` ブランチにある。**最後の手段**として、
   自分の実装と見比べる用途で使うこと（写すと何も身につかない）

## 開発の流れ（Git）

このリポジトリはテンプレートから作った自分専有のリポジトリなので、自由に使ってよい。
ただし以下を習慣にすること:

- 課題ごと・動いた区切りごとにコミットする（壊れたとき戻れる）
- コミットメッセージは「何をしたか」を 1 文で書く
- 先輩にレビューしてほしい場合はコラボレーターに追加して Pull Request を出す
