# 課題0: 開発環境と Lチカ — 「編集 → ビルド → 書き込み → 確認」を一巡する

実装するファイル: `Core/Src/app/app_main.c`（1行変えるだけ）

マイコン開発は「コードを書く」前に「環境を整えて書き込めるようにする」が最初の山。
ここを越えれば、あとの課題はこの繰り返しでしかない。

## 手順

### 1. 環境構築

1. **[環境構築ガイド](../環境構築.md)** に従って、自分の OS
   （Windows / macOS / Ubuntu）に Git・シリアルターミナル・
   ビルド用ツールを入れる
2. テンプレートから作った自分のリポジトリをクローンする

ビルドと書き込みの方法は 2 つある。**どちらでもよい**ので、片方を選んで §2 に進む。

| | A: CubeIDE | B: コマンドライン + ドラッグ&ドロップ |
|---|---|---|
| 追加で入れるもの | STM32CubeIDE（ST アカウント登録が必要） | `arm-none-eabi-gcc` と `make` だけ |
| デバッグ（ステップ実行） | できる | できない（printf で追う） |
| 詰まりやすさ | Import・Run 設定でつまずくことがある | ほぼつまずかない |

A を選んだ場合は続けて:

3. CubeIDE で File → Import → Existing Projects into Workspace →
   クローンしたフォルダを選択
4. Window → Preferences → General → Workspace →
   Text file encoding を **UTF-8** にする（日本語コメントが化けないように）

### 2. ビルドと書き込み

**A: CubeIDE の場合**

1. トンカチアイコン（Build）でビルドし、エラーが出ないことを確認する
2. マウスを USB で接続し、緑の再生アイコン（Run）で書き込む

**B: コマンドラインの場合**（詳細は[環境構築ガイド](../環境構築.md) §4）

1. リポジトリ直下で `make` を実行し、エラーが出ないことを確認する
2. マウスを USB で接続すると `NODE_F303K8` のようなドライブが現れるので、
   `build/wmmc-standard-mouse.bin` をそこにコピーする

どちらの場合も最後に:

3. 機体の LED が点き、スイッチでモード番号（LED1〜3 の2進数表示）が
   変わることを確認する

### 3. シリアル通信（printf）を見る

1. Tera Term（または CubeIDE 内蔵ターミナル、`screen`）で
   ST-Link の仮想 COM ポートを **115200bps** で開く
2. マウスをリセットし、起動バナー `***** WMMC Standard Mouse *****` が
   表示されることを確認する

### 4. Git の初期設定

[Git入門](../Git入門.md) の §1〜3 を読みながら、`user.name`/`user.email` の設定と
`git status → add → commit → push` の流れを確認しておく（次の手順で実際に使う）。

### 5. はじめての編集

1. `Core/Src/app/app_main.c` の起動バナーの printf の下に、
   **自分の名前を表示する printf を1行追加**する
2. ビルド → 書き込み → シリアルに表示されることを確認する
3. `git add` → `git commit` して、最初のコミットを作る

## 合格条件

- 自分の名前がシリアルに表示され、その変更がコミットされている
- スイッチでモードを選び、Mode 7（センサチェック）で AD 値が流れるのを見た

## つまずいたら

- ビルドは通るが書き込めない → USB ケーブルが「通信対応」か確認（充電専用ケーブルの罠）
- シリアルに何も出ない → ボーレート 115200 / ポート選択を確認
- それでもだめなら先輩へ。環境問題は一人で粘らないこと
